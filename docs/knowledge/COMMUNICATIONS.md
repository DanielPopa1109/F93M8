# F93 communications — current source view

CBM APP/FBL use STM32F411RE plus external MCP2515 SPI classic CAN. DMU APP/FBL use STM32F407VE bxCAN1. Each firmware image has its own Can/CanIf/CanTp/PduR sources. Routed diagnostics use standard CAN ID `0x710`, CBM target extended address `0x54`, DMU target `0x56`, response destination `0xF0`, and gateway FlowControl source `0x41`. Configured CanTp handles SF/FF/CF/FC with 256-byte buffers and a 5 ms main function. The native suites exercise segmented transfer, sequence/FC/timer errors and physical completion callbacks; electrical and on-bus timing are unverified.

The applications additionally have independent configured COM signals/PDUs and NM3 follower logic for one-byte standard ID `0x3FF` with active value `0xFF`. ComM/CanSM logically gate application TX; diagnostic traffic stays independently available. `28 01 03` now disables configured application TX while preserving normal COM RX. Default-session entry or S3 expiry restores TX. DMU's CanSM now retains its 200-tick silent recovery after bus-off, matching CBM's logical gate. Controller/transceiver recovery remains a bench gate.

Legacy CBM `CanSpi.c` and DMU `CanH.c` still own peripheral integration and ECU-specific receive effects. The configured COM path covers the current application PDUs, but complete AUTOSAR COM/NM/CanSM feature and concurrency review is open.
