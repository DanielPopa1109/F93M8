# F93 diagnostics

Both applications receive ZGW-routed extended-address requests through their own Can/CanIf/CanTp/PduR modules. CBM DCM (`CBM_APPL/BSW/Diag/Dcm/Dcm.c`) still converts short TP requests to an internal legacy single-frame dispatcher; its `0x700/0x701` values are internal to that adapter. DMU DCM (`DMU_APPL/BSW/Diag/Dcm/Dcm.c`) queues one complete TP request and dispatches it from a 5 ms task. Neither application has ZGW's configured service table, complete P2/P2* asynchronous handling or UDS DEM status model.

DMU DEM (`DMU_APPL/BSW/Diag/Dem/Dem.c`) now maps configured events `0x0E..0x16` to nine bounded `(event ID, status)` pairs in the existing 18-word persisted array. It aggregates hardware faults before updating events and validates restored pairs. This fixes the reported out-of-bounds writes. The DMU `19 0A` response still exposes the legacy raw pair encoding; it is not a standard configured UDS DTC record. DMU DCM now returns NRC `0x72` instead of acknowledging programming entry, reset or DTC clear when the immediate NvM write reports failure.

The independent FBLs still filter legacy request IDs (`0x700` CBM, `0x702` DMU) and do not have matching extended-address CanTp or the FCD programming sequence.
