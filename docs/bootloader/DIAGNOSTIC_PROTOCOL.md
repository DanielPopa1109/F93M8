# Current FBL diagnostic protocol

Both independent FBLs use standard classic CAN 0x710 with extended ISO-TP: CBM target 0x54, DMU target 0x56, gateway response destination 0xF0 and incoming gateway FlowControl 0x41. SF/FF/CF/FC are bounded to 256-byte UDS payloads. Real board completion/error feeds CanIf/CanTp; mailbox acceptance is not TP completion. The low-level MCP2515 and bxCAN implementations remain ECU-specific.

Services: session control, TesterPresent, F186 session read, application erase RID 0001, CRC RID 0002, RequestDownload 34 00 44 with BE32 address/size, BSC TransferData, TransferExit with optional CRC, and ECU reset. Maximum block length is 256 including SID/BSC. Duplicate identical blocks are acknowledged once; changed duplicates/wrong BSC fail. Long operations emit 0x78 and wait for physical confirmation. Resident activation RID 0155 fails closed in the default deployment build; the controlled enabled build emits physically confirmed NRC78 and transfers to the independent SRAM updater, which sends the final 0155 response only after owning CAN. CBM additionally retains its coding/calibration sessions with transactional parameter blocks; DMU does not inherit them.

See [closure report](../modernization/F93_REMAINING_GAPS_CLOSURE.md) for exact limits, [programming](FLASH_PROGRAMMING.md), and [executed evidence](../modernization/F93_VERIFICATION_RESULTS.md). FCD/ZGW route parameters were read from current source, but no routed bench exchange has been demonstrated.


The complete SRAM profile is in [RAM updater verification](RAM_UPDATER_VERIFICATION.md): select FBL block 02, activate RID0155, authorize resident range with RID0001, download 00/44, BSC TransferData, mandatory CRC-bearing TransferExit, then confirmed ECUReset. Physical resident erase is deliberately deferred to validated TransferExit. The SRAM profile keeps all responses <=6 UDS bytes, so they fit EA SF; gateway FC EA41 is ignored because no segmented response is outstanding. It emits EA F0 FC for segmented requests. Full resident segmented TX remains independently implemented. Both APP DCMs now accept FCD CommunicationControl type03, preserving the follower-NM behavior and diagnostic reception. No bus interoperability claim is made.
